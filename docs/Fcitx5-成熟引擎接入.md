# Fcitx5 成熟引擎接入

用户要求直接采用高关注度开源项目的通用排序与纠错。本版采用 Fcitx5 Android 官方 0.1.3 原生运行库、libime 解码器及官方 prebuilt 仓库的更新模型。调研时 Fcitx5 Android 约 5,900 stars；不会把 star 数当作所有输入都正确的保证。

微软 GitHub 的 Windows-classic-samples/Samples/IME/cpp/SampleIME 是输入法接口/词表查询示例，不是 Windows 自带微软拼音的完整中文模型。没有复制微软闭源库。

## 接入边界

- 26 键、默认简拼模式交给 Fcitx5 原生排序、纠错和学习；不使用本轮自写的前后缀扩词或倒序排序补丁。
- 九键、14 键与关闭简拼时保留原有 Rime 路径。空叶外观、手写、语音、翻译、密码填充和工具保留。
- 候选选择后，以原生返回的剩余拼音决定消耗量；界面不以汉字数猜测最终选词边界。
- 查询与不允许学习的输入场景设置原生 Sensitive 标记；仅用户允许学习且实际选词时开放学习。密码框绕过拼音。
- 不启用云拼音，不把输入发到服务器。

## 保留的界面调整

候选选择跟随按键振动强度；首选超过四个字时在右上方展示预览。连续添加拼音时保留已有候选，短时匹配失败不会缩为单一原文；保留项仍使用原先的拼音消耗边界，不能吞掉新输入。上方拼音按追加字母稳定分隔，不再被异步候选重新分词。

## 固定来源与重建

`app/src/main/assets/fcitx-sources.json` 记录官方 APK、上游模型提交与 SHA256；`python tools/fetch_fcitx.py` 恢复原生 AAR 和模型数据。源码及上游许可证一起交付。

## 效果的实际边界

上游更新模型实测能够直接把 nijuedzggzzmy、nijeudezggzzmy 排为“你觉得这个工作怎么样”，jeude 排为“觉得”，wsmyoudianka 排为“为什么有点卡”。这不是为例句增加的词条。

原生引擎仍会对歧义缩写给出不同解释，例如 budn 可能首选“不但能”；部分多余字母、v/u 混用长句未达到商业输入法效果。不得声称所有输入都必然符合意图，也不能为通过旧例子重新添加手工首选覆盖。


## 最终验收

Release 构建、lint 通过。索尼 A202SO Android 14 上，17 组原生整句和纠错检查通过，原生选词边界测试确认选择“你好”只消耗 nihao，整句消费全部输入。拼音逐字显示检查确认每次追加都保留之前显示的字符串前缀，不回头插入或删除分隔符。

真实软键快速输入并立即按空格的五项检查通过：nijuedzggzzmy、nijeudezggzzmy、jeude、wsmyoudianka，以及 nihaox 删除末字母后选词。最后一次触摸到读取确认上屏为 114–168 毫秒（含系统注入与无障碍读取开销）。右上预览与追加输入后候选保留已截图检查。

同一进程中 Fcitx5、Rime、神经手写和流式语音共存检查通过；36 个公开形变笔迹样本仍为首选，普通话公开音频样本增量识别通过。拼音编辑、面板动画、本地编辑、横屏与密码隐私回归通过。本轮未访问正式文档或真实密码空间。发行版本为 2.2.2。
