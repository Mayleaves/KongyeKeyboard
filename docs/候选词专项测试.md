# 拼音候选专项测试

## 当前规则

- 26 键支持全拼、声母简拼以及二者混合输入。主要候选使用 libime/Fcitx，另有 Rime 整句与回退路径。九键、14 键是其他布局，不等同于双拼方案。
- 保留合法歧义切分；手动 `'` 强制音节边界。最长显示切分不等于最终词语排序。
- 模糊音为可选的 12 组：z/zh、c/ch、s/sh、n/l、f/h、r/l、an/ang、en/eng、in/ing、ian/iang、uan/uang、v/u。测试逐条指定规则，默认关闭。
- 纠错包含邻键、相邻字母颠倒、多输、漏输四类，位掩码依次为 1、2、4、8；关闭测试逐项排除泄漏。不能把当前纠错实现概括为任意错拼都允许固定编辑距离。
- 基础候选由词典和语言模型提供，应用另有补全、整句纠错及个人词重排。没有“单字永远优先”或“长词永远优先”的通用规则。
- 个人学习在选词后发生；批量基线测试关闭其权重，不清空个人词库，不上屏或调用学习。另有 `learning-400` 模式覆盖计数、开关与淘汰规则。

以上规则对应 `Prefs.FUZZY_RULES`、`SpellingAssist`、`PinyinEngine`、`FcitxEngine` 和 `Lexicon`，不以提示词中的示例替代项目实现。

## 用例与判定

机器可读用例在 `app/src/androidTest/assets/pinyin-adversarial-v1.json`，首批固定 20 条。

- `expectedTop3` 是一组合理候选参考，未规定其唯一先后。少于三个合理结果时保留少量结果，不补入错音词或未输入的扩展词。
- `mustInclude` 检查完整消费输入的词是否能找到；只在展开列表出现时单独标记，不能冒充首屏排名合格。
- `forbiddenFull`、`offAbsent` 检查关闭规则后是否仍有完整匹配，以及强制隔音符是否被绕过。
- `watch` 是需要人工审查的靠前结果，不是全局禁字表。生僻词在正确读音下仍可被用户主动查找。
- 每条记录首批回调、完整查询、前 80 个候选的读音、消费字母数、来源及开关对照。耗时是引擎查询测量，不能当作触摸到文字显示的端到端延迟。
- 长句额外逐音节追加并记录候选覆盖下降；下降只标记复核，避免把合法的歧义回溯一概判错。
- 对重复无意义字母不硬造语义答案，验证有界查询、候选消费范围和重复结果。

## 执行

先构建应用及 `assembleReleaseAndroidTest`，复用已经连接的测试设备，并显式指定序列号：

```powershell
adb -s <设备序列号> shell am instrument -w -e mode pinyin-adversarial com.kongye.keyboard.test/com.kongye.keyboard.OfflineResourcesCheck
adb -s <设备序列号> pull /sdcard/Android/data/com.kongye.keyboard/files/pinyin-adversarial-v1/results.json build/pinyin-adversarial-results.json
python -X utf8 tools/format_candidate_review.py build/pinyin-adversarial-results.json build/pinyin-adversarial-report.md
```

报告会完整收集错误再失败，不因第一条异常停止后续用例。测试前后核对设置与个人学习文件，异常退出时也恢复运行时开关。

批量测试不能证明总体词频符合大众习惯。发现异常时先按原始输入、原生候选、应用重排、个人学习逐层定位；不要仅为让这 20 条通过而添加专用词条或固定首选。

## 第一轮定位结果

2026-11-25 在已运行的 API 37 模拟器上执行。`xi'an` 的首批原生结果正确，但后续 `HanReadings.complete` 去掉隔音符后补入了 `xian` 的单字，例如“先、线、现”。这属于应用补充路径的边界错误，已改为内部存在显式音节分界时不补充单音节字。普通 `xian` 和尾随分界 `xian'` 的补字仍保留，并用六组输入检查同类问题。

修复后：20 条用例的规则检查通过，另有 3 条排序观察保留人工评审标记；六组内部边界和尾随分界检查通过，407/407 个音节覆盖及原有歧义路径回归通过。个人学习文件和设置均保持不变。`huangg` 首选为“黄瓜”，`jeude` 首选为“觉得”，`shanxi` 同时保留“山西”和“陕西”。

本轮报告：`build/pinyin-adversarial-report.md`；机器结果：`build/pinyin-adversarial-results.json`；修复前结果：`build/pinyin-adversarial-before.json`。这些本机测试产物不打包进应用，也不替代后续真机输入手感验证。

排序观察不能直接当作修复依据：`niho` 可以补全为 `ni/hong`（霓虹），`nihzo` 可以按 `ni/h/zo` 匹配“你汇总”；“你好”是另一条纠错候选。关闭纠错后这些合法简拼不应被误删。长句中的“我镇”只消费 `wo/zhen`，是短前缀备选，不是吞掉整句的候选。是否需要调整这类相对排名，应另用更大语料及真实选择数据评审。
