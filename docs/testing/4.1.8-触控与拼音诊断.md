# 4.1.8 触控识别与拼音边界

## 平台边界

普通 Android IME 使用 MotionEvent 提供的逐触点坐标、历史坐标、触点 ID、工具类型和接触椭圆长短轴。系统没有向本项目提供触摸面板的电极网格、每个电极的强度或全部接触区域像素；本版本不能计算或宣称计算了硬件电极加权重心。坐标来自系统触控栈，不能把长短轴的包围框角点当成落点。

接口依据：[Android MotionEvent](https://developer.android.com/reference/android/view/MotionEvent)、[AOSP MotionEvent 源码](https://android.googlesource.com/platform/frameworks/base/+/master/core/java/android/view/MotionEvent.java)。原始电极采集属于设备/驱动能力限制，未完成且不冒充完成。

## 按层实施

| 阶段 | 实现与约束 |
| --- | --- |
| 采集与手势 | 按 pointer ID 跟踪，处理历史移动和抬手位移；普通键捕获按下时的命中键，明显误滑取消，不把抬手漂移改成邻键；不增加会吞快打的固定 50ms 最短按压门槛 |
| 热区 | 以实时绘制矩形派生有界扩展和距离轮廓，空格/删除/回车有更大余量；缩进空白和分体空隙不能无限归给边缘键，分词键边缘进一步隔离 |
| 空间打分 | 归一化中心距离、最多三个候选、距离/边界过滤、视觉核心区域保护；极小静态先验仅参与不确定边界，不宣称来自用户真实频率统计 |
| 上下文 | “边界处参考拼音”默认关闭。开启后仅在几何分数近似的字母边界使用合法音节前缀作小幅参考，不更改明确落点或原始输入串 |
| 个性化 | 设置 → 按键与手势 → 触控校准；明确提示目标字母，78 次主动点击后保存；只存相对偏移和计数/时间，偏移有上限，按方向/宽度/分体配置隔离，按 30 天半衰期衰减，可关闭和清空；普通打字不自动自证式训练 |
| 防误触 | 手指异常大接触区保守过滤、触控笔独立命中规则；设备可能不提供面积或提供不准确面积，不能宣称可靠识别所有手掌 |

保留已开启的滑行输入、上下滑符号、空格光标和删除手势。多指普通字母以按下顺序提交，第二指按下本身不提交第一指；兼容的候选/外观刷新保留尚未结束的触点。

## 拼音问题分层

显示用单引号与输入串中的手动隔音符是两个层次。显示层已有合法音节白名单、最长/较少音节优先及多路径图；本次不改成只保留一条贪心路径，也不为固定测试串写专用首选。

- `zhen` 必须保持完整音节；`zheme` → `zhe'me`、`jinzhun` → `jin'zhun` 的显示边界可以正常存在。
- “这么大”的全拼是 `zhemeda`；`zhemda` 缺少 e，可由简拼/纠错候选处理，隐藏分隔符不会补回字母。
- “精准”的全拼是 `jingzhun`；`jinzhun` 缺少 g，目标候选的覆盖和排名独立记录。
- “的是哪里”的全拼是 `deshinali`；`dvshinali` 含有 v。不能仅因用户期待就声称触控实际输出了 e，也不能把所有合法中英混输中的 V 全局删除。

诊断默认关闭。需要独立测试时，可用 adb 的 `log.tag.KongyeTouch` / `log.tag.KongyePinyin` DEBUG 标签获取触点命中、接受/取消、实际按键，以及 raw → display、手动边界/自动显示边界和字母保留检查。密码字段及内部输入条禁用日志；无需创建永久输入历史。日志用于定位来源，不是记录真实用户训练集。

## 验证要求

合成触控测试记录有标签的中心/偏移点、缝隙命中和拒绝、反序抬手与 pointer 索引变化、取消/明显横滑、快速短点、手掌样接触/触控笔、校准保存/关闭/清空/衰减、逐字拼音保留。上下滑、滑行、现有拼音和布局另行回归。

合成点命中率不能称为真人误触率；未经真实有标签用户测量，不给出“误触率降低百分比”。工具耗时不能称为触摸到屏幕显示的端到端延迟。未完成项和候选排名不足保留在工作记录中，不把通过触控回归等同于所有纠错和候选问题已修复。
